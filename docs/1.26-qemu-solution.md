# 1.26 兼容方案：QEMU 用户态

## 结论
BDS 1.26.62 在 Android 上通过 **QEMU 用户态模拟（qemu-x86_64-static）** 可以完整运行：
客户端能完成 NetherNet 信令、WebRTC/ICE、进入世界并 `Player Spawned`。
Box64/proot 下 1.26 的 NetherNet 会失败；QEMU 不经过 proot 的 syscall 拦截，是可行方案。

## 组件
- 手机：Redmi K30S Ultra / Android 17 / arm64 / 8GB
- qemu-x86_64-static 8.2.2（Ubuntu noble arm64 的 qemu-user-static 包，静态 ELF）
- x86_64 Ubuntu Base 24.04.3 rootfs（`-L` 指定）
- 官方 BDS 1.26.62.1 Linux x64
- 无需 proot、无需 Box64、无需 root

## 启动命令
```sh
cd /data/local/tmp/mcbds/server12662
tail -f cmd-qemu.log | ../qemu-x86_64-static -L ../rootfs-amd64 -cpu max ./bedrock_server
```
`cmd-qemu.log` 是控制台输入队列，追加一行就是一条命令。

## 实测
- `Server started.`
- 客户端 1.26.62（LeviLauncher 启动）成功进服：
  `[19:28:52] Player connected: SKJSLCY`
  `[19:31:54] Player Spawned: SKJSLCY`
- 服务端连续运行约 6 小时，直到调试用的 ADB 会话被关闭；无崩溃。
- 空闲 TPS：168 ticks / 8.348s ≈ **20.12 TPS**
- 内存：约 500–530MB；世界生成时 CPU 约 437%（多核）
- 在线模式（online-mode=true）仍然失败：
  `Could not connect to Minecraft services`，60 秒后退出。
  说明这是手机网络访问微软认证服务的问题，不是 Box64/QEMU 的指令模拟问题。
  当前只能用离线模式（online-mode=false, allow-list=false）。

## 注意
- 全新世界首次进入时 QEMU 生成出生点区块很慢（CPU 4 核以上），建议导入预生成存档或超平坦世界。
- QEMU 是 CPU 密集型，长时间开服需要充电和散热。
- 客户端必须与服务器版本匹配；1.26.62 客户端需用 LeviLauncher 启动（直接跑 exe 会 `Prerequisites-32`）。
- `server-udp-ports` 用范围（19140-19149），不要用映射形式。
